### Experiment 1: Linux files and directories
**Aim:** To practice basic Linux navigation and file-management commands.

**Commands:**
```bash
pwd
ls -la
mkdir module2_practice
cd module2_practice
touch notes.txt
echo "Linux practice" > notes.txt
cat notes.txt
cp notes.txt notes_backup.txt
mv notes_backup.txt backup.txt
```

**Procedure:** Run the commands in your own Linux environment. Observe the current directory, list files, create a folder and file, display its contents, and practice copying and renaming.

### Experiment 2: Linux permissions
**Aim:** To understand file permissions and permission changes.

**Commands:**
```bash
touch permission_demo.txt
ls -l permission_demo.txt
chmod 600 permission_demo.txt
ls -l permission_demo.txt
```

**Procedure:** Create a test file, inspect its permissions, change permissions to owner read/write only, and inspect again. Use only the test file created for this experiment.

**Observation:**  
Record the permission string before and after `chmod 600`.

**Result:** Linux file permissions were observed and modified on a test file.

### Experiment 3: Users, groups, and processes
**Aim:** To view account and process information.

**Commands:**
```bash
whoami
id
groups
ps
ps aux
```

**Procedure:** Run the commands and identify the current account, its group information, and examples of running processes. Do not terminate processes you do not recognize.

**Observation:**  
Record the current username, group information, and two example process names.

**Result:** User, group, and process information was examined.

### Experiment 4: Passive DNS reconnaissance
**Aim:** To understand basic DNS information gathering using a reserved example domain.

**Commands (if `dig` is installed):**
```bash
dig example.com
dig example.com A
dig example.com MX
nslookup example.com
```

**Procedure:** Query DNS records for `example.com`. This is an informational lookup; do not attempt to access or test systems discovered through DNS.

**Observation:**  
Record the query type and summarize the response. DNS answers may change over time.

**Result:** Basic DNS lookup and passive information gathering were demonstrated.

---

### Experiment 5: Localhost network scan with Nmap
**Aim:** To become familiar with Nmap output in a controlled local environment.

**Command:**
```bash
nmap 127.0.0.1
```

**Procedure:** Run the scan against the loopback address only. Review the host status and any port information reported. If Nmap is unavailable, note that and do not substitute a public target.

**Observation:**  
Record whether the host is reported up and summarize the output. A result with no open ports is valid.

**Result:** A basic Nmap scan was performed against the user's own computer only.

### Experiment 6: Wireshark traffic observation
**Aim:** To observe network packets generated by the user's own device.

**Procedure:**
1. Open Wireshark and select an interface belonging to your own computer.
2. Start a short capture.
3. Generate ordinary traffic by opening a known website or refreshing a page you are authorized to use.
4. Stop the capture.
5. Inspect packet details and note protocol names (for example, DNS, TCP, or TLS).
6. Save a sanitized screenshot. Do not share captured credentials, tokens, or private information.

**Observation:**  
Record the protocols observed and one general observation about packet details.

**Result:** Basic packet capture and protocol observation were completed on the user's own device.

---

### Experiment 7: Web proxy introduction – Burp Suite / OWASP ZAP
**Aim:** To understand how an intercepting proxy displays requests and responses in a controlled lab.

**Scope:** Use only a local training application running on your own computer, or an application explicitly provided for training. Do not proxy or test a third-party website.

**Procedure:**
1. Start Burp Suite Community Edition or OWASP ZAP.
2. Use its built-in browser or configure a browser specifically for the local lab.
3. Open the local training application.
4. Browse a harmless page and observe the request and response in the proxy history.
5. Do not attempt exploitation, authentication bypass, or data extraction.
6. Stop the proxy and close the lab when finished.

**Observation:**  
Record the tool used and describe the request/response fields you could identify (such as method, path, status code, and headers). Do not include cookies or tokens.

**Result:** The role of a web proxy in observing HTTP requests and responses was understood.
